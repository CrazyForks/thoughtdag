# 换了一个新问题，怎样接上以前和 AI 讨论过的思路？

一篇新论文让你想起之前放弃的方法。你记得当时嫌它太慢，却记不清问题出在算法、设备，还是部署条件。把“太慢，不做”这句结论直接交给 AI，可能会漏掉当时真正的限制。

ThoughtDAG 是开源 AI 对话画布，可以检索受支持的本地 Agent 对话。下面用手动找回、核对、引用的流程，把旧判断接到一个新问题上。

## 准备：确认旧讨论在本机

使用能访问本机索引的 ThoughtDAG 桌面版，并配置用于回答问题的模型。旧讨论需要保存在受支持的本地来源中；仅存在于网页账号里的历史不会自动出现。

从欢迎页的“Agent 对话”，或画布左上菜单的“Agent 对话地图”进入。先在“接入”中检查来源目录，再回到会话列表，按项目和会话标题找到旧讨论。点击会话卡片，将它导入为画布镜像。

## 1. 在新问题旁边找相关旧讨论

回到准备继续工作的画布。本文采用手动引用，练习时先关闭输入区的“回忆”，再建立一个用于重新评估旧方案的新问题节点。已有问题节点也可以使用，但需核对它原先的回忆和材料。

双击新问题节点打开侧栏，展开“相关对话”。调整搜索词，例如换成旧讨论里确实出现过的方法名、文件名或“本地运行”。基础词检索依赖原话命中，宽泛地搜“那个想法”可能找不到。

仅看到结果不会把它们自动接入当前画布上下文。如果找不到，先检查来源和索引，再换成更具体的原词。配置了可用的判断模型后，可以尝试“让模型扩展”，得到更多搜索词；这一步不是手动引用的前提。

## 2. 先看原话和条件

打开命中的来源，读相关轮次：当时究竟排除了什么？哪些条件现在变了？不要只凭摘要就把旧结论当作今天仍成立的事实。

看来源可能切到旧会话的镜像。核对完后，回到原画布，重新选中需要引用的新问题节点，再展开“相关对话”。

## 3. 引用有用的部分，继续追问

点击所需结果的“引用”。选中了目标节点时，引用会成为带来源的材料节点，并连接到它；没有选中目标时，只会放到画布上，需要你再连线。

检查引用材料的正文。较长轮次可能被截短，省略标记提醒你回源补齐必要部分。移除无关内容，保留判断所需的原话与条件，再检查上下文预览。旧条件已经失效时，说明哪里变了，避免把修改后的文字误当成原始记录。

引用加入后，现有回答不会自动改写。你可以重新生成回答，也可以继续追问：“当时因为算力成本放弃了这条路线。结合新论文的方法，哪些限制可能改善，哪些还需要验证？”

从同一个问题分支，还可以单独检查“能否本地运行”。

## 使用边界

画布的修改不会重写来源 Agent 的日志。索引只覆盖已接入并可识别的本地记录，不能恢复从未保存的历史。

若开启输入区的“回忆”，系统也会在发送时检索并带入历史。回忆区会显示这次带入的条目；排除条目后，需要重新生成，已经发送过的请求不会被撤回。

调用远端模型时，参与请求的材料会发送给配置的模型服务；本地索引不等于整个问答过程离线。

旧讨论现在有了可追溯的入口。你可以核对哪些条件仍成立，再决定这次沿什么方向往下想。
